# 🔬 AI Research Gap Explorer

Распределённая система на Python для анализа корпуса научных публикаций. Она импортирует метаданные и 768-мерные эмбеддинги, строит двумерные проекции и модели кластеризации, автоматически описывает тематики и ранжирует кандидатов на research gaps.

Research gap в интерфейсе — вычислительная гипотеза, которую должен проверить исследователь, а не доказательство отсутствия работ.

## ✅ Что уже реализовано

- Сформулирована задача анализа тематической структуры научного корпуса и поиска
  кандидатов на research gaps. Описаны четыре пользовательских сценария.
- Система разделена на пять независимых Python-микросервисов: Collector,
  Storage, ML Service, Web Master и Visualization.
- Collector проверяет исходные файлы, вычисляет SHA-256-версию набора и выдаёт
  публикации батчами с журналированием операций.
- Storage предоставляет CRUD API для исходных и обработанных данных. Публикации
  и эмбеддинги хранятся в PostgreSQL/pgvector, а модели, проекции, тематики и
  research gaps — в связанных таблицах и Docker volume.
- ML Service независимо обучает KMeans/MiniBatchKMeans и PCA/UMAP, сохраняет
  версии и артефакты моделей, рассчитывает Silhouette, Davies–Bouldin,
  Calinski–Harabasz и inertia и применяет кластеризатор к новым эмбеддингам Автоматически называет кластеры по TF-IDF-терминам, считает статистику и временную динамику тематик. Оценивает близость тем и ранжирует потенциальные исследовательские пробелы.
- Web Master служит единой точкой входа, организует импорт и ML-сценарии,
  маршрутизирует запросы и преобразует ошибки внутренних сервисов.
- Реализован интерактивный Dash-интерфейс для импорта, обучения, сравнения и
  удаления моделей, просмотра метрик, тематической карты, трендов и пяти лучших
  gap-кандидатов.
- Подготовлен README с запуском, пользовательскими сценариями, описанием архитектуры и команды управления.

## 🏗️ Архитектура

```text
Browser
   │
   ▼
Visualization (Dash, :18050)
   │ REST
   ▼
Web Master (FastAPI, :18000)
   ├──► Collector (FastAPI, :18001) ──► data/ (read-only)
   ├──► Storage (FastAPI, :18002) ────► PostgreSQL + pgvector
   └──► ML Service (FastAPI, :18003) ─► model-data volume
                    │
                    └──────── REST ───► Storage
```

Каждый прикладной сервис имеет собственные `Dockerfile`, `requirements.txt` и REST API. Внутри Docker Compose сервисы обращаются друг к другу по DNS-именам контейнеров. Visualization работает только через Web Master; прямой доступ к БД есть только у Storage.

Структура репозитория:

```text
data/                      входной набор
services/
  collector/               чтение, проверка и пакетная выдача данных
  storage/                 БД, CRUD и хранение результатов
  ml_service/              проекции, кластеризация и анализ тематик
  web_master/              API Gateway и пользовательские сценарии
  visualization/           многостраничный Dash-интерфейс
docker-compose.yml         сборка, сеть, healthcheck и volumes
.env.example               параметры окружения
README.md                  запуск и состояние требований
```

## 📁 Входные данные

Перед запуском в каталоге `data` должны находиться три обязательных файла:

```text
data/
  papers.csv               метаданные научных публикаций
  embedding_ids.csv        порядок публикаций в матрице эмбеддингов
  embeddings.npy           матрица 768-мерных эмбеддингов
```

## 🚀 Запуск

```powershell
docker compose up -d --build
docker compose ps
```

Когда контейнеры станут `healthy`, откройте:

- интерфейс: http://localhost:18050;
- публичный Swagger Web Master: http://localhost:18000/docs;
- Swagger Collector: http://localhost:18001/docs;
- Swagger Storage: http://localhost:18002/docs;
- Swagger ML Service: http://localhost:18003/docs.

Порядок работы в интерфейсе:

1. На странице «Импорт данных» перенесите набор в Storage.
2. На странице «Способы визуализации» создайте PCA или UMAP.
3. На странице «Модели» обучите один или несколько кластеризаторов и сравните метрики.
4. На странице «Результаты» выберите совместимые модель и проекцию.

## 🛠️ Управление

```powershell
# Логи всех сервисов
docker compose logs -f

# Логи одного сервиса
docker compose logs -f ml-service

# Пересобрать только изменённый сервис
docker compose up -d --build visualization

# Остановить, сохранив БД и артефакты
docker compose down

# Удалить контейнеры, БД и артефакты моделей
docker compose down -v
```

## 🎯 Пользовательские сценарии

Перед выполнением сценариев пользователь один раз импортирует подготовленный
корпус. Импорт является подготовительным этапом, после которого доступны четыре
основных пользовательских сценария.

1. **Обучение модели кластеризации.** Пользователь выбирает KMeans или
   MiniBatchKMeans, задаёт число кластеров и доступные гиперпараметры. ML Service
   нормализует эмбеддинги, обучает модель и определяет кластер каждой публикации.

2. **Обучение модели проекции.** Пользователь выбирает PCA или UMAP и настраивает
   параметры выбранного алгоритма. Система преобразует 768-мерные эмбеддинги в
   двумерные координаты, необходимые для интерактивной карты.

3. **Cравнение моделей.** Пользователь может обучить несколько моделей кластеризации и   несколько моделей визуализации с разными алгоритмами и гиперпараметрами. Модели кластеризации отображаются в сортируемой benchmark-таблице с Silhouette Score, Davies–Bouldin Index, Calinski–Harabasz Index и inertia, поэтому их можно сравнивать количественно. Модели визуализации PCA и UMAP сохраняются в отдельном списке и сравниваются визуально: пользователь поочерёдно совмещает их с одной моделью кластеризации на странице результатов и оценивает, насколько хорошо каждая проекция показывает структуру тематик.

4. **Исследование тематической карты и research gaps.** Пользователь выбирает завершённую
   модель кластеризации и совместимую двумерную проекцию. Система объединяет их
   результаты по `paper_id` и показывает публикации на тематической карте,
   окрашивая точки по кластерам. Пользователь может фильтровать публикации по
   годам, изучать развитие тематик во времени, просматривать таблицу тем и
   раскрывать пять лучших кандидатов на research gaps с их оценкой, близостью
   тематик и числом пограничных публикаций.
